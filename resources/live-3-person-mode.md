# Live 3-Person Mode

Purpose: run the workshop for three experienced developers in the room without turning it into a self-paced MOOC. The 65-LE map remains the facilitator scaffold and self-learner track; live delivery uses conversation, pair-driving, and short Socratic checks.

---

## Default Live Shape

Use this for the actual cohort of three:

1. **See it:** facilitator shows the PPT/demo beat.
2. **Drive it:** one participant drives Claude Code on the playground.
3. **Think aloud:** the driver says what they expect Claude to do before pressing Enter.
4. **Navigate:** the second participant watches scope, permissions, and tests.
5. **Observe:** the third participant watches cost, context, and transfer-to-work-repo relevance.
6. **Rotate:** switch driver/navigator/observer every major hands-on beat.

No one silently completes a dashboard checklist during live teaching. The cockpit is for facilitator routing and self-study after the session.

---

## Role Cards

| Role | Watches | Says out loud |
|---|---|---|
| Driver | Prompt, command, approval | "I expect Claude to..." |
| Navigator | Scope, permission, file boundary | "This is safe/unsafe because..." |
| Observer | Cost, context, transfer | "In our work repo this maps to..." |

If one setup breaks, pair immediately: broken-machine participant becomes Navigator while the facilitator debugs in parallel.

---

## Per-LE Socratic Prompts

Use one prompt per LE instead of asking participants to complete quizzes live.

| LE family | Prompt |
|---|---|
| Foundations | "What real action did Claude just take, and what permission made it possible?" |
| Context / Memory | "What must be written down so the next session behaves the same?" |
| Prompting | "What scope boundary would stop this from becoming too broad?" |
| Git | "What would make this PR reviewable by another developer?" |
| Skills / Hooks / Plugins | "Is this a reusable procedure, an automatic trigger, or a bundle?" |
| MCP / RAG | "What data crossed a boundary, and who owns it?" |
| Agents | "Which part should be parallel, and which part must stay coordinated?" |
| Security | "What finding is confirmed, and what is only plausible?" |
| Automation | "What stops this if it gets expensive, wrong, or stale?" |
| Capstone | "What evidence makes the handoff ready for tomorrow's work repo?" |

---

## Timing Rule

For every 30 minutes of live time:

- 10 min teaching/demo
- 12 min think-aloud pair-driving
- 5 min group debrief
- 3 min buffer or transfer note

When time is tight, cut dashboard completion and quizzes first. Keep the live build, the safety question, and the transfer note.
