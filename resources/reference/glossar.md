# Glossar

Wofür: die Begriffe dieser Bibliothek in einem Satz, jeweils mit dem Kapitel, das sie erklärt. Begriffsnamen bleiben
Englisch, wo sie Bezeichner sind.

Geprüft gegen die offizielle Doku am 2026-09-30 (CLI 2.1.285). Offizielle Quelle: https://code.claude.com/docs/en/glossary

Das offizielle Glossary (Englisch) ist ausführlicher und verlinkt jede Doku-Seite. Alte Namen und den Reifegrad der
Funktionen findest du auf der [Karte „Alte Namen"](karte-alte-namen.md), Zahlen zu Modellen und Preisen nur im
[Kanon](../_canonical.md).

| Begriff | Bedeutung | Kapitel |
|---|---|---|
| `Agent` (Tool) | Eingebautes Tool, das einen Subagenten mit eigenem Kontextfenster startet; hieß bis v2.1.63 `Task`. | [S3.2](../library/s3-02-eingebaute-subagenten.md) |
| Agent Teams | Mehrere eigenständige Claude-Code-Sitzungen unter einer Teamleitung, mit gemeinsamer Aufgabenliste und direkten Nachrichten untereinander; experimentell und standardmäßig aus. | [S3.5](../library/s3-05-hintergrund-und-teams.md) |
| `AGENTS.md` | Anweisungsdatei für Coding-Agenten aus dem Codex-Umfeld. Fehlt eine `CLAUDE.md`, liest Claude Code sie als Projektanweisung (ab v2.1.277); gibt es beide, nur die `CLAUDE.md`, außer sie importiert `@AGENTS.md`. Fallen: [Karte „Kontext"](karte-kontext.md#agentsmd-neben-claudemd). | [S1.12](../library/s1-12-imports-und-agents-md.md) |
| `AskUserQuestion` | Eingebautes Tool für Multiple-Choice-Rückfragen; damit fragen Skills und Agenten strukturiert nach. | [S1.4](../library/s1-04-werkzeuge.md) |
| Auto-Memory | Notizen, die Claude selbst schreibt, je Git-Repository unter `~/.claude/projects/<projekt>/memory/` mit dem Index `MEMORY.md`; standardmäßig an, Schalter in `/memory`. Aufräumen und Abschalten: [Karte „Kontext"](karte-kontext.md#auto-memory-drift). | [S1.11](../library/s1-11-gedaechtnis-ebenen.md) |
| Bare mode (`--bare`) | Start ohne automatische Erkennung von Hooks, Skills, Plugins, MCP-Servern, Auto-Memory und `CLAUDE.md`, für CI und Skripte. Liest kein Abo-Token (`CLAUDE_CODE_OAUTH_TOKEN`), Zugang über `ANTHROPIC_API_KEY` oder einen `apiKeyHelper`. Kein Schalter, der Auto-Memory dauerhaft abstellt. | [S4.3](../library/s4-03-headless.md), [S4.4](../library/s4-04-ci-zugang-und-kosten.md) |
| Built-in Tools | Die festen Tools von Claude Code, etwa `Read`, `Edit`, `Write`, `Bash`, `Grep`, `Glob`, `Agent`, `Skill`, `WebFetch`. Ihre Namen sind die Strings für Rechte-Regeln, Hook-Matcher und Tool-Listen; vollständig in der [Tools-Referenz](https://code.claude.com/docs/en/tools-reference). | [S1.4](../library/s1-04-werkzeuge.md) |
| Bundled Skills | Mitgelieferte, prompt-basierte Playbooks wie `/batch`, `/code-review`, `/debug`, `/doctor`, `/loop`, `/claude-api`, `/run`, `/verify`, `/fewer-permission-prompts`; anders als eingebaute Commands mit fester Logik. | [S2.4](../library/s2-04-mitgelieferte-skills.md) |
| Channels | MCP-Server, der Ereignisse in eine laufende Sitzung schiebt, auch in beide Richtungen wie eine Chat-Brücke; Research Preview. | [S4.6](../library/s4-06-remote-und-teleport.md) |
| `CLAUDE.md` | Anweisungsdatei, die bei jedem Sitzungsstart lädt: im Projekt (`./CLAUDE.md` oder `./.claude/CLAUDE.md`, eingecheckt), für dich (`~/.claude/CLAUDE.md`, alle Projekte) oder von der Organisation. Alle gefundenen Dateien werden aneinandergehängt, keine überschreibt die andere. | [S1.10](../library/s1-10-claude-md.md), [S1.11](../library/s1-11-gedaechtnis-ebenen.md) |
| `CLAUDE.local.md` | Persönliche Projektnotizen neben der `CLAUDE.md`, nicht eingecheckt (in `.gitignore` aufnehmen). | [S1.11](../library/s1-11-gedaechtnis-ebenen.md) |
| Command | Befehl, den du mit `/name` aufrufst. Eingebaute wie `/clear`, `/model`, `/compact` steuern die Sitzung; eigene Commands in `.claude/commands/` funktionieren weiter, empfohlen sind Skills. „Slash Command" ist der alte Name. | [S2.1](../library/s2-01-skills-und-commands.md), [S2.3](../library/s2-03-wer-skills-ausloest.md) |
| Custom Skill | Skill von dir oder deinem Projekt, weder aus einem Plugin noch mitgeliefert: `~/.claude/skills/<name>/SKILL.md` oder `.claude/skills/<name>/SKILL.md`. | [S2.2](../library/s2-02-skill-schreiben.md) |
| Dynamic Context Injection | `` !`befehl` `` in einem Skill setzt die Ausgabe eines Shell-Befehls in den Prompt ein; abschaltbar mit `disableSkillShellExecution`. | [S2.5](../library/s2-05-lebendige-prompts.md) |
| Effort | Wie viel das Modell nachdenkt, von `low` bis `max`, je Modell verschieden. Wahl nach Aufgabe: [Kostenkarte](karte-kosten.md). | [S1.7](../library/s1-07-modellwahl-und-effort.md) |
| Geschützte Pfade | Pfade wie `.git`, `.claude` (außer `.claude/worktrees`), Shell-Configs und `.mcp.json`, auf die kein Modus Schreibzugriffe automatisch genehmigt, außer `bypassPermissions`; Allow-Regeln ändern daran nichts. Liste und Verhalten je Modus: [Karte „Rechte"](karte-rechte.md#geschützte-pfade-protected-paths). | [S3.9](../library/s3-09-geschuetzte-pfade-und-sandbox.md) |
| Hintergrund-Sitzung | Sitzung, die losgelöst vom Terminal läuft (`claude --bg` oder `/background`); verwalten mit `claude agents`; Research Preview. Alle Griffe: [Karte „Agenten"](karte-agenten-worktrees.md#hintergrund). | [S3.5](../library/s3-05-hintergrund-und-teams.md) |
| Hook | Eigener Handler, der an einem festen Punkt im Ablauf automatisch läuft, etwa vor einem Tool oder beim Sitzungsstart. Drei Ebenen: Ereignis, Matcher, Handler. Steht in `settings.json` oder im Frontmatter von Skills und Subagenten. | [S2.6](../library/s2-06-hooks-als-sensoren.md) |
| Hook-Ereignis | Zeitpunkt, an dem ein Hook feuert, etwa `PreToolUse`, `PostToolUse`, `Stop`, `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreCompact`, `SubagentStart`, `SubagentStop`, `FileChanged`, `InstructionsLoaded`, `Notification`. Wann welches feuert: [Karte „Hooks"](karte-hooks.md#ereignisse-für-den-alltag). | [S2.7](../library/s2-07-hook-ereignisse.md) |
| Hook-Typ | Wie ein Handler arbeitet: `command` (Shell), `http`, `mcp_tool`, `prompt` (Bewertung durch ein Modell), `agent` (Subagent). | [S2.9](../library/s2-09-hook-typen.md) |
| Kontextfenster | Arbeitsspeicher einer Sitzung: Verlauf, Dateiinhalte, Befehlsausgaben, `CLAUDE.md`, Skills, Systemanweisungen. `/context` zeigt die Belegung, `/compact` fasst zusammen; Größen je Modell stehen im Kanon. | [S1.8](../library/s1-08-kontextfenster.md), [S1.9](../library/s1-09-kontext-steuern.md) |
| Kostengrenze | `--max-budget-usd` begrenzt die Ausgaben, `--max-turns` die Agenten-Runden eines Laufs; beide nur mit `-p`. Details: [Kostenkarte](karte-kosten.md). | [S1.19](../library/s1-19-kosten-im-blick.md), [S4.4](../library/s4-04-ci-zugang-und-kosten.md) |
| Marketplace | Plugin-Katalog, den ein Repository in `.claude-plugin/marketplace.json` definiert. Anthropic betreibt drei allgemeine: `claude-plugins-official`, `claude-community` und `claude-code-plugins` (Beispiele). Hinzufügen: `claude plugin marketplace add <quelle>`. | [S2.12](../library/s2-12-plugin-lebenszyklus.md) |
| MCP | Model Context Protocol: offener Standard, der KI-Werkzeuge mit externen Diensten und Datenquellen verbindet. | [S2.14](../library/s2-14-mcp-stecker.md) |
| MCP-Scope | Wo eine Server-Konfiguration steht: `local` (Standard, nur dieses Projekt), `project` (`.mcp.json` im Repo-Root, eingecheckt), `user` (alle deine Projekte). `local` und `user` liegen in `~/.claude.json`, nicht unter `.claude/`. Tabelle: [Karte „Erweitern"](karte-erweitern.md#mcp-scopes). | [S2.15](../library/s2-15-mcp-einrichten.md) |
| MCP-Server | Programm, das Claude über MCP Tools, Prompts oder Ressourcen gibt. Transporte: HTTP (für entfernte Server empfohlen), stdio (lokaler Prozess), SSE (veraltet). | [S2.15](../library/s2-15-mcp-einrichten.md) |
| Memory | Drei Arten von Gedächtnis: `CLAUDE.md` (schreibst du), Auto-Memory (schreibt Claude) und die gespeicherten Sitzungsverläufe unter `~/.claude/projects/`. | [S1.11](../library/s1-11-gedaechtnis-ebenen.md) |
| Modell | Das Tier hinter Claude Code: `fable` (Premium), `opus` (Default), `sonnet` (Standard-Coding), `haiku` (Bulk-Arbeit, kleineres Kontextfenster). Wechsel mit `/model` oder `--model`; Generationen und Preise im Kanon, Wahl nach Aufgabe auf der [Kostenkarte](karte-kosten.md). | [S1.7](../library/s1-07-modellwahl-und-effort.md) |
| `Monitor` (Tool) | Führt einen Befehl im Hintergrund aus und meldet jede Ausgabezeile an Claude, damit es mitten in der Sitzung auf Logs, Dateiänderungen oder Status reagiert. | [S1.4](../library/s1-04-werkzeuge.md) |
| Non-interactive mode | Früher „Headless": `claude -p` führt einen Prompt aus und endet; für CI, Skripte und Pipes. | [S4.3](../library/s4-03-headless.md) |
| Plan-Modus | Rechte-Modus, in dem Claude liest, untersucht und einen Plan vorlegt, bevor es Dateien ändert; `/plan` oder `Shift+Tab`. | [S1.14](../library/s1-14-plan-modus.md) |
| Plugin | Installierbares Bündel aus Skills, Hooks, Subagenten, MCP-Servern und weiteren Teilen; Plugin-Skills heißen `plugin-name:skill-name`. Kommt aus einem Marketplace oder lokal per `--plugin-dir`. | [S2.11](../library/s2-11-plugins-buendeln.md) |
| Plugin-Manifest | `.claude-plugin/plugin.json` im Plugin, nicht im Plugin-Root. Optional: Ohne Manifest lädt Claude Code die Teile aus dem Standard-Layout. | [S2.11](../library/s2-11-plugins-buendeln.md) |
| Plugin-Scope | Für wen ein Plugin aktiviert ist: `user`, `project`, `local` oder `managed`. Eingetragen wird das unter `enabledPlugins` in der Settings-Datei des Scopes, nicht in einem Plugin-Ordner. Dateien je Scope: [Karte „Erweitern"](karte-erweitern.md#plugin-baum). | [S2.12](../library/s2-12-plugin-lebenszyklus.md) |
| RAG | Retrieval-Augmented Generation: Das Modell antwortet aus einer externen Wissensquelle statt aus dem eigenen Gedächtnis; in Claude Code meist über einen MCP-Server angebunden, etwa NotebookLM. | [S2.18](../library/s2-18-rag-und-notebooklm.md) |
| Rechte-Modus | Grundverhalten der Sitzung: `default` (Anzeige „Manual"), `acceptEdits`, `plan`, `auto` (ein Klassifizierer prüft statt dir; ab v2.1.283 Startmodus im Terminal und in VS Code), `dontAsk`, `bypassPermissions` (nur in Container oder VM). Wechsel mit `Shift+Tab` oder `--permission-mode`. Was jeder Modus erlaubt: [Karte „Rechte"](karte-rechte.md#die-sechs-modi). | [S1.5](../library/s1-05-rechte-im-alltag.md), [S1.6](../library/s1-06-rechte-modi.md) |
| Rechte-Regel | Eintrag unter `permissions.allow`, `ask` oder `deny` in `settings.json`, etwa `Bash(npm test *)`, `Read(./.env)`, `WebFetch(domain:github.com)`. Geprüft wird deny, dann ask, dann allow; der erste Treffer entscheidet. Verwalten mit `/permissions`; Muster: [Karte „Rechte"](karte-rechte.md#regeln-allow-ask-deny). | [S1.5](../library/s1-05-rechte-im-alltag.md), [S3.8](../library/s3-08-rechte-fuer-autonomie.md) |
| Routine | Gespeicherte Konfiguration aus Prompt, Repositories und Connectoren, die in der Cloud automatisch läuft: nach Zeitplan, per API-Aufruf oder bei GitHub-Ereignissen; anlegen mit `/schedule`; Research Preview. | [S3.12](../library/s3-12-zeitgesteuert-arbeiten.md) |
| Rules | Anweisungsdateien in `.claude/rules/`; mit `paths:` im Frontmatter laden sie erst, wenn Claude eine passende Datei liest. | [S1.11](../library/s1-11-gedaechtnis-ebenen.md) |
| Sandbox | Datei- und Netzwerk-Isolation auf Betriebssystemebene für das Bash-Tool, eine eigene Schicht neben den Rechte-Regeln; `/sandbox`. | [S3.9](../library/s3-09-geschuetzte-pfade-und-sandbox.md) |
| Session | Unterhaltung mit eigenem Kontextfenster, gebunden an das Verzeichnis. Fortsetzen mit `claude -c` (letzte) oder `claude -r <id oder name>`; `/clear` beginnt eine neue, die alte bleibt über `/resume` erreichbar. | [S1.9](../library/s1-09-kontext-steuern.md) |
| Skill | `SKILL.md` (Markdown mit YAML-Frontmatter) mit Anweisungen oder einem Ablauf. Claude lädt ihn selbst, wenn er passt, oder du rufst `/<name>` auf. Ablage: Organisation, persönlich (`~/.claude/skills/`), Projekt (`.claude/skills/`), Plugin. | [S2.1](../library/s2-01-skills-und-commands.md), [S2.2](../library/s2-02-skill-schreiben.md) |
| Skill-Frontmatter | YAML-Kopf einer `SKILL.md`, etwa `name`, `description`, `when_to_use`, `disable-model-invocation`, `allowed-tools`, `paths`. `version`, `author` und `tags` gehören nicht zum offiziellen Schema, eigene Angaben stehen in `metadata`. Felder und Fallen: [Karte „Erweitern"](karte-erweitern.md#skill-frontmatter-der-kern). | [S2.2](../library/s2-02-skill-schreiben.md) |
| Skill Live-Reload | Änderungen an einer `SKILL.md` unter `~/.claude/skills/` oder `.claude/skills/` wirken ohne Neustart (nicht im Bare mode). Neu angelegtes Skill-Verzeichnis: `/reload-skills`; Plugin-Teile wie `hooks/`: `/reload-plugins`. | [S2.2](../library/s2-02-skill-schreiben.md) |
| Subagent | Spezialisierter Assistent mit eigenem Kontextfenster, Systemprompt, Tools und Rechten; erledigt eine delegierte Aufgabe und liefert eine Zusammenfassung zurück. Eingebaut: Explore, Plan, general-purpose; eigene in `.claude/agents/`, `~/.claude/agents/` oder per `--agents`. | [S3.1](../library/s3-01-was-ist-ein-agent.md), [S3.3](../library/s3-03-eigener-subagent.md) |
| Subagent-Frontmatter | YAML-Kopf einer Agent-Datei, etwa `name`, `description`, `tools` (nicht `allowed_tools`), `model`, `permissionMode`, `isolation`. Die Alltagsfelder: [Karte „Agenten"](karte-agenten-worktrees.md#subagent-datei-die-alltagsfelder). | [S3.3](../library/s3-03-eigener-subagent.md) |
| Surface | Ort, an dem du Claude Code nutzt: CLI, VS Code, JetBrains, Desktop-App, claude.ai. Alle nutzen dieselbe Engine; lokale Sitzungen lesen deine `CLAUDE.md` und Settings, Cloud-Sitzungen starten aus einem frischen Klon des Repositorys. | [S1.3](../library/s1-03-oberflaechen.md) |
| Task-Tools | `TaskCreate`, `TaskGet`, `TaskList`, `TaskUpdate` für Aufgabenlisten in der Sitzung, Nachfolger von `TodoWrite`; standardmäßig nur auf älteren Modellen, sonst mit `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`. | [S1.4](../library/s1-04-werkzeuge.md) |
| Telegram-Bridge | Eigenes Muster dieses Kurses: ein Bot, der Claude-Code-Sitzungen über Telegram steuert, kein Anthropic-Feature. Offizielle Wege sind Channels (Telegram gehört zur Research Preview) und Remote Control. | [S4.6](../library/s4-06-remote-und-teleport.md) |
| Token | Abrechnungseinheit für Ein- und Ausgaben eines Modells; `/usage` zeigt den Verbrauch der Sitzung, Preise je Modell stehen im Kanon. | [S1.19](../library/s1-19-kosten-im-blick.md) |
| Trigger Phrase | Worte in `description` (und `when_to_use`) eines Skills, an denen Claude erkennt, wann der Skill passt; präzise Formulierungen verhindern Fehlauslösungen. | [S2.3](../library/s2-03-wer-skills-ausloest.md) |
| Worktree | Zusätzlicher Arbeitsbaum desselben Git-Repositorys auf eigenem Branch. `claude --worktree <name>` (`-w`) legt ihn unter `<repo>/.claude/worktrees/<name>` an, Subagenten bekommen ihn mit `isolation: worktree`. | [S1.18](../library/s1-18-worktrees.md) |
| `worktree.baseRef` | Setting mit zwei Werten: `fresh` (Standard, zweigt vom Default-Branch des Remotes ab) oder `head` (vom lokalen `HEAD`, mit unveröffentlichten Commits). Die Falle dazu: [Karte „Agenten"](karte-agenten-worktrees.md#die-worktreebaseref-falle). | [S1.18](../library/s1-18-worktrees.md) |
